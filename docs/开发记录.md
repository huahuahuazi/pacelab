## 2026-11-13 · v1.0：从一句话需求到能装上手机的 App

### 原始需求（一字未改）

> 做一个可直接在手机操作的软件：用户填跑步数据或提供跑步图片 → 分析当前跑步水平 →
> 预测 5K/10K/半马/全马成绩 → 数据制成曲线表格展示 → 提供"生成计划"按钮，选距离后生成计划，
> 每天后面加"完成"按钮，点击确认完成后邀请用户填本次数据（配速或图片），图片要提取内容。
> 产物以后要能转发到 GitHub。**本程序要求不上传到云端，完全自主在手机端完成。**

### 从需求里定下的三条硬边界

1. **全本地** —— 没有服务器、没有账号、没有网络请求。这是用户明确要求的，也决定了后面所有技术选型。
2. **一个人能维护** —— 不做微服务、不引框架、不加构建链。一个人月改得动的代码才有生命力。
3. **能装到手机** —— 不只是网页，要出 APK。但不需要上架应用商店。

### 技术选型与理由

| 决策 | 选择 | 为什么，以及否掉了什么 |
|---|---|---|
| 前端 | 纯静态 PWA，ES Modules，零框架零构建 | 这个体量上 Vue/React 只会让"改一行要起 dev server"变成日常负担。零构建 = 双击 index.html 就能跑，也能直接丢 GitHub Pages |
| 数据存储 | localStorage（键 `pacelab.state.v1`）+ JSON 导入导出 | 没有 IndexedDB 的复杂度，也不够格用 SQLite。附带的导入导出是**数据主权**：用户随时能把数据带走 |
| 跑步算法 | Daniels **VDOT** 反算 + Riegel 公式外推 | VDOT 是行业事实标准，E/M/T/I/R 五档配速直接对应训练类型。Riegel（`T₂=T₁×(D₂/D₁)^1.06`）比线性外推准得多，1.06 这个指数是被验证过的 |
| 训练计划 | 自研生成器，不做模板库 | 模板库对不上任何人的实际水平。生成器有两条红线：**周跑量增幅 ≤10%**（防伤，这条是拿伤病换来的经验）、**质量课 ≤2 次/周**；外加赛前减量 |
| OCR | Tesseract.js v5，引擎随包分发 | 见下方「为什么不用云 OCR」 |
| 安卓壳 | 自写 WebView + `WebViewAssetLoader`（280 行 Java） | **否掉了 Capacitor**：它为了几个原生能力引入一整套构建链和依赖树，而我们只需要"加载本地网页 + 接住文件选择"。280 行自己写，出问题自己看得懂 |
| 图表 | 手写 SVG | 引 Chart.js 是 200KB 换几个折线图，不值 |

### 为什么不用云 OCR

用户要求"不上传云端"，但即使没这条要求，也**不该**用云 OCR：

- 每传一张截图就是一次隐私出网（截图里常有位置、设备、心率）
- 断网就废，而跑步的人经常在没信号的地方
- 有调用成本，有配额，有第三方可用性依赖

代价是本地引擎 11MB 打进了 APK。**用 11MB 换掉一整个服务依赖，这笔账划算。**

### 安卓侧的一个关键技术点

`WebViewAssetLoader` 把 assets 映射到 `https://appassets.androidplatform.net`，
而不是用 `file://` 直接加载。原因：`file://` 协议下 ES Module 会被 CORS 拦住，
整个页面白屏。这个坑不踩一次想不到。

## v1.1：上传打不开 + 保存不了

### 现象

用户报两个问题：上传图片识别不了、手动输入保存不了。

### 根因：是同一个 bug

弹层模板是 `<div class="sheet" onclick="event.stopPropagation()">`，
而全局点击监听绑在 `document` 的**冒泡阶段**。

点弹层里任何按钮 → 事件在 `.sheet` 层被 `stopPropagation()` 掐断 → 传不到 `document`。

**「保存」「取消」「全部填入」全是死按钮**，点了没反应，控制台也不报错。

修法两条：
1. 监听改绑**捕获阶段**：`document.addEventListener('click', handleClick, true)`
2. 去掉内联 `stopPropagation`，遮罩关闭改成判断 `e.target === el`

### 第二个坑：WebView 不对 `display:none` 的 file input 触发文件选择

原来 `<input type="file" class="hide">`，`.hide` 是 `display: none`，
再用 JS 调 `.click()`。

**桌面 Chrome 允许，Android WebView 不允许。** 所以网页版好使、装到手机就失灵。

改成透明覆盖层，让手指直接点到原生 input：

```css
.file-tap { position: absolute; inset: 0; opacity: 0; width: 100%; height: 100%; }
```

系统级点击，不经过 JS，也不受内核版本限制。用 `elementFromPoint` 实测命中 `<INPUT id=f-file>`。

### 顺带修的

- **用时改成时/分/秒三格**，空的按 0 算。输入框从 `type="number"` 改 `type="text" inputmode="decimal"`——
  中文输入法在 number 类型下会吞值，这也是"填了保存不了"的诱因之一。
- **toast 从底部挪到顶部**：模态框 + 键盘弹起时，底部提示必然被遮挡，校验失败了用户根本看不见。
- **老 WebView 白屏**：`app.js` 里有一处可选链 `?.`。minSdk 24 的机器 WebView 可能停在 Chrome 60-79，
  解析到就抛 SyntaxError，**整个文件加载失败、打开就是白屏**。改 if 判断，
  并加了 `tests/syntax-compat.test.mjs` 卡住可选链 / 空值合并 / 正则后行断言 / 逻辑赋值四类语法。

### 教训（这条最重要）

**DOM 替身测试直接调 handler，天然绕过事件冒泡和真实文件选择**，测不出"点了没反应"这类 bug。

所以必须有真跑浏览器的端到端链路（`tools/verify-upload.mjs`）。这一条后来救了两次。

## v1.2：识别结果离谱

### 现象

用户上传一张 vivo WATCH GT2 的运动卡片，识别出：距离 1.4km / 用时 7:38:26 / 配速 327'27"。
实际是：1.55km / 8:05 / 5'12"。

### 诊断：先复现，别猜

第一步不是改代码，是**把原始识别文本 dump 出来**。建了 `tools/run-variants.mjs`：
同一张图 × 4 种预处理 × 3 种版面分割模式（PSM），12 组结果全打出来。

结果出乎意料——**Tesseract 全读对了**：

```
... 1 55 Bea ... F47:38:26 ... 5'12" 0:08:05 ... 1,404 ... 8.18x ...
```

`1.55`、`5'12"`、`0:08:05` 都在文本里。**失败的是解析层，不是 OCR。**

### 三个错误叠加

| # | 图上真实内容 | OCR 读成 | 旧逻辑的处理 | 结果 |
|---|---|---|---|---|
| 1 | `1.55 公里` | `1 55 Bea`（小数点丢、单位糊） | 匹配不到单位，退回找独立小数 | 捞到 `1,404 步` → **1.4 km** |
| 2 | `下午7:38:26`（右上角日期） | `F47:38:26` | 三段冒号就当时长，还排在 `0:08:05` 前面 | **7 小时 38 分** |
| 3 | `平均配速 5'12"` | ✅ 唯一读对的 | 用「距离÷时长」判它"不一致"，反被改掉 | **327'27"/km → VDOT 0.0** |

第 3 行是最要命的：**唯一认对的数，被两个错数"纠正"掉了。**
根因是 `pickBest` 取各自候选的 `[0]`，谁先出现用谁，而且三个字段的互相校验链路是单向的。

### 修法

**1. 双 PSM 识别，文本合并**

PSM 3（自动分块）把 `1.55` 读成 `1 55`；PSM 11（稀疏文本）能读回 `1.55`，
但会把状态栏电量信号全捞进来。**两个都不全对，但错的地方不一样** → 合并候选池。

代价 0.4s → 0.8s，换小数点不丢，值。

**2. 候选池 + 一致性网格搜索**

不再"取第一个"，而是把所有候选交叉组合，找物理上自洽的那组：

```
候选：距离 [1.55, 8.1]  用时 [485, 27506]  配速 [194, 312]

1.55 × 312 = 483.6 ≈ 485   （误差 0.3%）← 唯一自洽，评 high
1.55 × 194 = 300.7 ≠ 485   （差 61%）
8.1  × 312 = 2527  ≠ 485   （差 420%）
```

**3. 千分位不是小数**

`1,404 步` 经 `parseFloat` 变成 `1.404`——把步数当距离的头号原因。
现在 `\d{1,3},\d{3}` 一律不当小数。

**4. 日期时间降权，但不硬删**

往前 44 字符内有 `20xx|年|月|日|上午|下午` → 标记"疑似时钟"，打分扣 40。

**不直接丢弃是有意的**：真跑了 4 小时的人，不该因为画面里有 `7:00:12` 就丢掉 `4:11:30`。
所以是降权 + 让一致性校验决定。这条专门写了测试用例。

**5. 一个衍生 bug**

三段时长兜底改成"有完整 h:mm:ss 就别退到两段猜"，并加 `(?![\d:])`。
否则 `0:08:05` 会被切成 `0:08`，候选池里冒出"配速 8 秒"这种鬼东西。

### 一个被实验否掉的决策

我原本准备加"反色"（深色底截图常见的修法）。

实测：**反色前后识别结果逐字相同**。Tesseract 内部已经做了极性判断，
加这一步只是白烧 200ms。

**这个结论没有实测就只能靠猜。** 所以诊断工具留下了，以后再遇到类似疑问先跑一遍。

### 界面同步改的

原始识别文本之前直接铺在首屏（`7005808 @& elle 8b 22%...`），占大半屏。
用户看到一堆乱码只会以为程序坏了。改成 `<details>` 默认折叠，首屏只放结论。

低置信度不自动填入 + 换图先清空三个字段（以前"新图没认出来，上次的错值还躺在输入框里"）。

## 贯穿全程的工程约定

| 约定 | 具体做法 |
|---|---|
| **测试用真实数据** | `tests/ocr-parse.test.mjs` 的输入全是真实 OCR 输出，不是手写的理想数据。手写数据永远测不出"小数点丢了""单位糊了" |
| **失败可观测** | 识别失败分三种：引擎没加载 / 图片解码失败 / 认不出字段，提示各不相同，都不静默 |
| **离线优先** | 引擎本地优先、CDN 只是兜底。APK 里引擎已打包，全程无网也能用 |
| **降级不中断** | 图片预处理失败就用原图硬跑；识别彻底失败就提示手动填。任何一环失败都不阻塞用户记账 |
| **契约冻结** | `localStorage` 的 `pacelab.state.v1` 结构定稿后不动；要改就升版本号并写迁移 |

## 2026-11-13 晚 · v1.3：跑法体系重构 + 体能画像 + 逐日可改

### 用户报的四个问题，先分清哪些是真 bug

| 用户描述 | 判断 | 结论 |
|---|---|---|
| 生成计划「无论选什么都是 10K、每周三练」 | 一半真一半是感知问题 | 见下方详述 |
| 日期「下面显示的周一是 11月13日」但 13 号是周五 | **真 bug** | 起始日没对齐到周一，整周七天错位 |
| 配速区间名字看不懂 | 产品问题 | 改成六种跑法 |
| 计划不能改、不能自定义 | 功能缺失 | 新增逐日编辑 + 空白骨架 |

**关于「选什么都没用」的诚实结论：**

`case 'seg'` 这个处理器本来就在，实测点击能切换、参数能正确传给生成器。
我第一次用 `grep "seg:"` 搜的时候漏了 `seg':` 这个写法，误判成"处理器缺失"，
于是加了一份重复的 `case 'seg'` —— 后来发现并删掉了。

真正让用户觉得"没生效"的是另一件事：**训练天数被静默降级**。
近 30 天跑量折合每周不到 18km 时，`plan.js` 会把 5 练降成 3 练（否则就是每天 3km 的假训练），
但界面上一个字都不说。用户看到的是"我选了 5 练，出来还是 3 练"，
自然推论是"选什么都没用"。**静默降级的破坏力比 bug 还大** —— 它会让人对整个系统失去信任。

修法：生成后明确说出来「当前跑量撑不起 5 练，按 3 练排」。

### 日期错位：一个不会报错的错

`startDate` 被直接当成第 0 天用，而第 0 天恒等于"周一"。
用户选 11/13（周五），那天就被渲染成「周一 11月13日」，后面六天全部顺移。

不报错、不崩溃，只是每天都是错的。这种 bug 只能靠"日期和星期必须自洽"的断言抓：

```js
const wd = new Date(d.date + 'T00:00:00').getDay();
const expect = (wd + 6) % 7;
assert.strictEqual(d.dow, expect);
```

修法是向后对齐到"不早于所选日期的第一个周一"。向后不对齐向前，是因为向前会落到已过去的日期，
把第一周变成半周。

### 跑法体系：从 E/M/T/I/R 改成六种人话

原来的命名混了两套逻辑：「轻松跑/门槛跑/重复跑」是训练法，「马拉松配速」是速度。
跑者看完不知道自己今天该跑什么。

新体系：**恢复跑 / 轻松跑 / 节奏跑 / 间歇跑 / 冲刺跑 / 法特莱克**，
每种给四样东西：配速区间、心率区间（%HRR）、步频目标、以及一句体感判断（"能边跑边完整说一句话"）。

比赛配速（M）单独列，不占六格 —— 它是"要用的速度"，不是"训练的方法"。

配速给**区间**而不是单点：只给一个数，人会为了"跑准"频繁看表，反而跑变形。

### 体能画像：宁可显示「—」也不给假分

四个维度，每个 0-100：

1. **有氧能力** — VDOT 映射。以 VDOT 40 = 50 分为基准（能跑完半马、配速 6 分左右的典型业余跑者）。
   不用 `(vdot-20)/50` 那种线性映射，那会让 VDOT 30 的人只得 20 分，可他明明能跑完 10km 了。
2. **心率效率** — 同样配速下心率占储备的百分比，减去该配速的理论值。
3. **步频经济性** — 160-180 步/分是高效区；步频低 + 步幅明显偏大判为跨大步。
4. **负荷安全** — ACWR（近 7 天跑量 ÷ 近 28 天周均），1.0-1.3 安全，>1.5 是伤病高发区。

**为什么没有单独一维"步幅"**：速度 = 步幅 × 步频，速度固定时两者是反比关系，
单独给步幅打分等于把同一个信息算两遍。步幅放进步频维度一起判断。

两条"不编造"的硬规则：
- 心率与配速的偏差超过 ±20% 时**返回 null**，不评分。这通常意味着数据本身矛盾
  （超常发挥把 VDOT 抬高了、心率带飘了、那天发烧），给分就是编造。
- 有数据维度少于 3 个时，**综合分显示「—」**。靠一项算出来的总分没有意义。

### 心率区间：Tanaka + Karvonen，缺参数就说"这是估算"

最大心率用 `208 - 0.7 × 年龄`（Tanaka 1997），不用 220-年龄 —— 后者在 40 岁以上系统性高估。
目标心率用储备心率法：`静息心率 + 强度% × (最大心率 - 静息心率)`。
同样 70%，久坐的人和一个常年跑的人实际强度差得远，减掉静息心率之后才可比。

缺年龄/静息心率时按 30 岁 / 65 估算，并把 `estimated` 标进界面 —— 不能让用户当成实测值。

### 逐日编辑与自定义计划

## 2026-11-13 深夜 · v1.4：数据驱动的火柴人

### 需求

首页「当前跑步水平」卡片加一个侧面跑步视角的火柴人，**动作按近 7 天真实数据生成**，
右上角气泡标注近期状态并指向小人，让人一眼明白"这个小人就是我自己"。

### 关键决策：动画参数必须来自数据，不能是装饰

装饰性动画谁都会做。这个功能有意思的地方在于三个视觉参数各自绑定一个真实指标：

| 视觉 | 数据 | 映射 |
|---|---|---|
| 摆腿周期 | 步频 | `cycle = 120 / cadence` 秒（一个完整周期是左右各一步） |
| 摆腿幅度 | 步幅 | `20 + (步幅 - 70) × 0.4` 度，夹在 20–46 |
| 身体前倾 | 配速 | `3 + (460 - 配速秒) × 0.05` 度，夹在 3–15 |

170 步频和 174 步频动起来确实不一样。用户看到的不是一套固定动画，是自己的节奏。

### 一个真 bug：步幅公式单位错了

`60000 ÷ (配速 × 步频)` 出来的是**米**，我却当厘米用，结果「312s/km + 174spm → 步幅 1 厘米」。

- `strideFromPace()` 少乘 100
- `buildFitnessProfile` 里的 `idealStride` 同样错
- `recentRhythm` 里也错

三处一起改成 `× 100`。**这个错在纯文本测试里看不出来，只有把数字显示到界面上才会暴露**（步幅 1cm 一眼假）。
教训：单位换算函数必须有带真实数值的断言，不能只测"返回值是数字"。

### 技术选型：SMIL 而不是 CSS animation

SVG 元素做 CSS 旋转要依赖 `transform-box` / `transform-origin` 的像素坐标支持，
Chrome 60 档的老 WebView 不一定认。SMIL 从 Chrome 2 就支持，安卓上更稳，
而且能直接嵌在模板字符串里，不用额外 CSS。

`<animateTransform type="rotate" values="34 90 88;-34 90 88;34 90 88" dur="0.697s">`
—— values 里的三元组是「角度 中心x 中心y」。

### 三次迭代才做对的动画

1. **第一版**：火柴人太高，腿被卡片底边裁掉
2. **第二版**：缩小重排，能看但动作像"跨步站立"
3. **第三版**：试了大小腿两段（膝盖关节）——**折角小了看不出动作，折角大了像腿断了**，
   两条腿都在折的样子像弯腰驼背。回退到单段直线的钟摆，反而更像在跑。
4. **最终**：加 `calcMode="spline"` 缓动，让腿在前/后两个极端位置停留更久
   （跑步落地本来就有支撑期，匀速摆动像节拍器）；前腿略长于后腿，
   交叉相位时才不会完全重合成一条。

**教训：火柴人这个抽象层级上，干净的钟摆比解剖正确更重要。**

### CSS 层叠踩的坑

给描述文字加让位用的 `margin-right` 一直不生效——因为前面 `.hero .desc { margin: 10px 0 0 }`
用了 margin 简写，会把 `margin-right` 重置成 0。同样的优先级下后出现的规则获胜，
所以让位规则单独放在文件末尾收口，而不是去改前面的简写（改简写容易影响别处）。

### 状态判定（runnerMood）

三个信号，都能从数据直接算：
- **负荷**：ACWR（近 7 天 ÷ 近 28 天周均），>1.5 伤病高发区，1.0–1.3 安全爬升
- **频率**：这周跑了几次
- **配速趋势**：近 7 天 vs 之前两周，只在两边都有 ≥2 次记录时才比（否则噪音大于信号）

输出六种状态：最近没跑 / 刚回到跑道 / 这周加量偏猛 / 量在往上加 / 状态在回升 /
配速有点掉 / 节奏挺稳 / 正在减量。

点气泡弹出说明，把「为什么是这个状态」和「近 7 天四个数」都摊开，
并明确写一句"小人跑的就是你自己最近一周的样子"。

### 新增工具

`tools/verify-runner.mjs` —— **验证动画真的在动**。
SVG 里 animate 写错了图形照样显示，只是不动，静态截图完全看不出来。
这个脚本在小人区域隔 340ms 截两次比像素哈希：一样就是死的。
顺带断言 `.runner-art` 完整落在卡片内（第一版就是被裁的）。

## 2026-11-15 · v1.6：图标黑底修复 + 首页两栏 + 计划档位与周数

### 1. 图标「白底」是生成脚本的锅（P0）

用户报桌面图标是白底。逐像素查了 6 个文件，问题比看上去严重：

## 2026-11-15 晚 · v1.8：质量课不再被「跑量统计不足」抹掉

### 问题
用户反馈生成的计划**全是轻松跑**，要求按正常训练学安排
冲刺跑、间歇跑、法特莱克、节奏跑，并明确：
「只是因为当前数据统计不足而产生的对跑者的误判，要按预测成绩的水平安排」。

### 根因（两处，都在 plan.js）
1. 生成循环里 `if (tpl.quality.includes(slotIdx) && km >= minKm)`：
   主课 ≥3km、次课 ≥5km 才排质量课。用户周均 15.5km 摊到 5 练，
   每节课约 2~3km → **次课永远不达标**，全部降级成轻松跑。
2. `makeQuality` 只会在 间歇 / 节奏 / 比赛配速 里选，
   **压根没有法特莱克和冲刺跑**。

这是典型的「用近期跑量误判能力」：记录少 ≠ 只能跑轻松跑。

### 改法
1. **删掉距离门槛**：质量课 slot 一律排质量课，距离小就排短而真的课。
   `makeQuality` 增加 `total<3.5` 一档热身/冷身（0.8/0.4），
   2km 也能排出 5×100m 加速跑，body 最少 0.8km。
   `distKm` 仍等于分配到的总距离，周跑量守恒不破。
2. **四类课按阶段＋周序轮转**（`QUALITY_PAIR` / `QUALITY_SOLO`）：
   一周 2 次质量课是业余跑者安全上限，不硬塞四种强度；靠跨周轮转覆盖四类。
   3 练只有 1 次质量课，走 4 周 SOLO 循环，否则冲刺跑永远轮不到主课位置。
   减量周强制轻量（加速跑 / 法特莱克）；比赛配速跑只对半马/全马，短距离目标回落间歇。
3. **配速全部取 `trainingPaces(vdot)` 的 T/I/R/M/E** —— 和预测成绩同一个 VDOT，
   不由这一周跑了多少公里决定。

### 验证
算法用例 26 → 30，新增：
- 周均 0km 时 3/4/5 练都排得出四类质量课
- 三档强度不删质量课类型（只改跑量）
- VDOT 30 与 50 的首节质量课配速不同（6'24" vs 4'15"）
- 短距离质量课有可执行内容（组数/主体距离）且每日距离之和 = 总跑量

端到端 26 项、动画 8 项、上传 11 项全过。
实测课表：周二法特莱克 2.9km（3 组变速，快段 6'55"、慢段 8'15"），不再是轻松跑。
